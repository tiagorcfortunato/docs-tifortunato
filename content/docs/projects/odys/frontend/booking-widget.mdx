# Booking Widget

The `BookingWidget` component, located at `src/app/p/[slug]/booking-widget.tsx`, serves as the primary interface for clients to schedule appointments with professionals. It is a crucial frontend component embedded within each professional's public profile page (`src/app/p/[slug]/page.tsx`), enabling a streamlined, self-service booking experience.

## Overview

This client-side React component orchestrates a multi-step booking process, guiding users from selecting a date and time to providing their contact information. It leverages a combination of local React state, `react-hook-form` for robust form management and validation, and `date-fns` for precise date and time manipulations. The widget interacts with the backend via the `/api/booking` API route to fetch availability and submit new appointments. The entire flow is designed to be intuitive, breaking down the booking into three distinct steps: `pick` (date and time), `form` (client details), and `success` (confirmation).

## State Management and Flow

The `BookingWidget` manages its interactive experience through several `useState` hooks, central to which is the `step` variable, controlling the current stage of the booking process. This state machine transitions through three main phases:

1.  **`pick`**: The initial state where users select a desired date and an available time slot.
2.  **`form`**: After a slot is chosen, the user proceeds to fill out their personal details.
3.  **`success`**: Upon successful submission, a confirmation message is displayed, potentially including payment instructions.

Other key state variables include `selectedDate` and `selectedSlot` to track user choices, `slots` to store the computed available times, `loadingSlots` and `loading` to provide feedback during asynchronous operations, and `submittedData` to retain client information for the success screen.

## Date and Time Selection

In the `pick` step, the user interacts with a `Calendar` component (from `src/components/ui/calendar.tsx`) to choose a date. This calendar is configured to use the `ptBR` locale and disables past dates using `isBefore(date, startOfDay(new Date()))`.

A `useEffect` hook monitors changes to `selectedDate`. Whenever a new date is selected, it triggers an asynchronous operation to fetch available slots for that specific day. This involves:

1.  Formatting the `selectedDate` into `yyyy-MM-dd`.
2.  Making a GET request to the `/api/booking` endpoint, passing the `slug` of the professional and the formatted `date`.
3.  The API response provides the professional's `AvailabilityRule`s and `ExistingAppointment`s for the chosen day.
4.  These data points, along with the professional's `sessionDuration` (from the `professionals` table), are fed into the `generateSlots` utility function located in `src/lib/slots.ts`.

The `generateSlots` function is responsible for calculating all potential booking times. It iterates through the professional's defined `startTime` and `endTime` for the `dayOfWeek`, incrementing by `sessionDuration` minutes. Crucially, it filters out any slots that are in the past or conflict with `existingAppointments`. The resulting `slots` are grouped by the `groupSlots` helper function, defined in `src/app/p/[slug]/booking-widget.tsx`. Users select a specific `slot` by clicking on a `SlotButton` (defined in `src/app/p/[slug]/booking-widget.tsx`). Once both a `selectedDate` and `selectedSlot` are chosen, the "Continuar" button becomes active, transitioning the widget to the `form` step.

## Client Information Form

The `form` step presents a client data entry form. This form is managed using `react-hook-form`, integrated with `zodResolver` for schema validation against `clientSchema`. The schema defines required fields like `name` and `phone`, and an optional `email`. The client information form uses `Input` (from `src/components/ui/input.tsx`) and `Label` (from `src/components/ui/label.tsx`) components.

A notable feature of this form is the inclusion of a "honeypot" field named `website`. This input is visually hidden, has `tabIndex={-1}`, `aria-hidden="true"`, and `autoComplete="off"`. Its purpose is to deter automated spam bots: a human user will never fill it, but a naive bot might. On the server side, any submission with a non-empty `website` field is silently discarded, effectively filtering out spam without requiring complex CAPTCHAs.

If the user is logged in and not the professional themselves, their existing `name`, `phone`, and `email` (fetched from the `clients` table in `src/app/p/[slug]/page.tsx`) are used as `defaultValues` to pre-fill the form, enhancing user convenience.

Upon submission, the `onSubmit` function constructs the `startsAt` timestamp using the `selectedDate` and `selectedSlot`. It then sends a POST request to `/api/booking` with the professional's `slug`, the `startsAt` time, and the client's `name`, `phone`, `email`, and the honeypot `website` field. A successful booking triggers a `booking_created` event capture via `posthog` and transitions the widget to the `success` step. Errors are handled by displaying a `toast.error` message.

## Booking Confirmation

The final `success` step provides a confirmation message, reiterating the booking details. It dynamically displays a `PixQR` component (from `src/components/pix-qr.tsx`) if `paymentType` is not "after" and `pixKey` is available. The `pixAmount` is calculated based on `sessionPrice` and `paymentPercentage`.

For users who are not logged in, the widget presents an invitation to create a free account. This invitation includes a dynamically generated registration URL (`/register`) with pre-filled `searchParams` for `name`, `email`, and `phone` from the `submittedData`, simplifying the signup process. Logged-in users are offered a direct link to their appointments dashboard.

## Design Decisions

*   **Client-Side Component**: The `BookingWidget` is marked `"use client"` because it relies heavily on interactive features like state management (`useState`), form handling (`react-hook-form`), and direct browser API calls (`fetch`, `window.location`). This client-side rendering is essential for a dynamic user experience.
*   **Three-Step Flow**: Breaking the booking process into `pick`, `form`, and `success` steps improves user experience by reducing cognitive load. Each step focuses on a single task, making the process feel less daunting and more manageable. This modular approach also simplifies state management and error handling for each stage.
*   **`react-hook-form` and `zod`**: This combination was chosen for its performance benefits (minimal re-renders), strong validation capabilities, and developer ergonomics. `zod` provides type-safe schema validation, ensuring data integrity before submission, while `react-hook-form` efficiently manages form state and submission.
*   **Honeypot Spam Prevention**: The `website` honeypot field is a lightweight, non-intrusive method for filtering out automated spam. It avoids the friction of CAPTCHAs, which can negatively impact user experience, especially for legitimate users. The trade-off is that it might not catch more sophisticated bots, but it's effective against common, naive spam attempts.
*   **`generateSlots` as a Pure Function**: The slot generation logic is encapsulated in `generateSlots` within `src/lib/slots.ts`. This design choice promotes reusability and testability, as the function is pure and deterministic, taking inputs (`date`, `rules`, `existingAppointments`, `sessionDuration`) and returning a predictable output.
*   **`date-fns` for Date Manipulation**: `date-fns` was selected for its comprehensive, immutable, and modular approach to date manipulation. Its functions, like `format`, `addMinutes`, `isBefore`, and `isAfter`, are crucial for accurately calculating and comparing time slots, ensuring correctness across different time zones and daylight saving scenarios.

## Potential Improvements

*   **Server-Side Slot Pre-computation**: Currently, the `useEffect` hook fetches slots client-side after the component mounts. For the initial `selectedDate` (which could default to today), the slots could be pre-computed on the server within `src/app/p/[slug]/page.tsx` and passed as a prop to `BookingWidget`. This would reduce the initial loading state for slots and improve perceived performance.
*   **Input Masking for Phone Number**: The `phone` input in the `clientSchema` currently only validates length. Implementing an input mask (e.g., `(XX) XXXXX-XXXX`) would improve user experience by guiding input format and reducing validation errors. This could be done using a client-side library or a custom `onChange` handler for the `Input` component in `src/app/p/[slug]/booking-widget.tsx`.
*   **More Granular Error Handling for Slot Fetching**: If the `fetch` call to `/api/booking` fails when loading slots (e.g., network error, server issue), the current implementation only shows "Carregando horários...". A more specific error message, such as "Erro ao carregar horários. Tente novamente.", could be displayed by introducing an `errorSlots` state variable in `src/app/p/[slug]/booking-widget.tsx`.
